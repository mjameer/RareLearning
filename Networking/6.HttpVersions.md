## HTTP Protocol Evolution: HTTP/1 vs HTTP/2 vs HTTP/3

### Introduction
This repository explains the differences between HTTP/1, HTTP/2, and HTTP/3, highlighting why HTTP/3 was introduced and its advantages over previous versions.

## HTTP Version Progression

| **Version**  | **Key Features** |
|-------------|----------------|
| **HTTP/1 (1996)** | Each request requires a separate TCP connection, leading to high latency. |
| **HTTP/1.1 (1997)** | Introduced **keep-alive**, allowing connection reuse, but requests are processed sequentially, causing **head-of-line blocking**. |
| **HTTP/2 (2015)** | Added **multiplexed streams** over a single TCP connection, fixing application-layer blocking but retaining **TCP head-of-line blocking** at the transport layer. |
| **HTTP/3 (2022)** | Uses **QUIC over UDP**, enabling **independent streams**, eliminating transport-layer **head-of-line blocking**, and improving mobile performance. |

### HTTP 1
- Simply put, every request to the same server, requires a new TCP connection. 

### HTTP/1.1 (1997 – Legacy Standard)
- Introduced keep-alive, allowing a connection to be reused for multiple requests, reducing latency.
- Persistent connections eliminate the need for a new TCP three-way handshake for every request.
- A same TCP be reused for connection same server. However, it still processes requests sequentially (i.e., one at a time per connection), which can cause delays due to head-of-line blocking.
- **Head-of-line blocking**: issue: If one request is delayed (e.g., due to packet loss), all subsequent requests in the same connection are blocked.
- High **latency**, requiring multiple TCP connections for faster performance.
- Inefficient **resource usage**, making web pages load slower.

### HTTP/2 and Its Limitation

<img width="778" alt="Screenshot 2025-02-01 at 6 39 02 PM" src="https://github.com/user-attachments/assets/8081ca81-7ad7-4fc4-b4eb-ea1d76f49233" />

- HTTP/2 introduced HTTP streams, where **multiplexed streams** request are sent over a **single TCP connection**, allowing multiple HTTP requests to be sent concurrently.
- However, **TCP enforces in-order delivery**. If one packet is lost, **all subsequent packets** are blocked until it is retransmitted.
- This issue, known as **TCP head-of-line blocking**, significantly **slows down web performance**, especially in lossy networks.
- So basically its fixed the **TCP head-of-line blocking** at the application layer, but not at the transport layer (TCP).
- Introduced server push, allowing servers to send updates (SSE) to clients without requiring polling.


## HTTP/2 vs. HTTP/3

### Why Was HTTP/3 Invented?
HTTP/3 was created to solve the **head-of-line blocking** issue in **HTTP/2**, which arises from **TCP’s ordered delivery mechanism**.

<img width="831" alt="Screenshot 2025-02-01 at 6 43 02 PM" src="https://github.com/user-attachments/assets/e0218386-58c5-4aa9-a400-585db1c47b2b" />

### How HTTP/3 Solves the Problem
- HTTP/3 is built on top of **QUIC**, which runs over **UDP** instead of TCP.
- QUIC introduces **independent streams**, at Transport layer, meaning packet loss in one stream does **not** block others.
- **Eliminates head-of-line blocking** since streams are independent.
- Since **UDP does not enforce ordering**, QUIC **manages its own retransmission per stream**, ensuring faster and more efficient data delivery.
- This prevents the bottleneck issue seen in HTTP/2, making web pages load more smoothly, even in unreliable network conditions.
- Built-in **TLS 1.3 encryption** for enhanced security.
- This was forced to be created, as mobile-heavy usage—users frequently switch networks (e.g., Wi-Fi → cellular).
- QUIC’s uses something called Connection ID, which allows seamless switching between IP addresses and network interfaces without reconnecting.


#### Conclusion on HTTP/2 vs. HTTP/3
By replacing TCP with QUIC, **HTTP/3 ensures better performance, lower latency, and improved reliability**, particularly for mobile and high-latency connections.


### Is HTTP/3 Available?
✅ **Yes!** HTTP/3 is already implemented in:
- **Chrome, Firefox, Edge** (default support).
- **Google, Facebook, Cloudflare** (major companies using it).



### Conclusion
HTTP/3 is the **future of web communication**, solving latency and reliability issues faced by HTTP/1 and HTTP/2. Adoption is growing, making the web faster and more efficient!
